# Отчет по исследовательскому тестированию сервиса hh.ru

**Цель:** Изучение архитектуры, бизнес-логики и рисков продукта в условиях отсутствия проектной документации.

---

## 1. План исследования на неделю

### Первые 2 дня: Разведка и картирование
* **User Journeys:** Прохождение ключевых пользовательских сценариев за две основные роли — **Соискатель** и **Работодатель**.
* **MindMap:** Составление карты экранов, функциональных модулей и связей между ними.
* **Анализ API:** Фиксация сетевых запросов через DevTools (Network tab) для понимания REST/GraphQL структуры приложения.

### День 3–4: Проверка бизнес-логики и интеграций
* **Основные механики:** Создание и публикация объектов (резюме/вакансий), работа поискового движка, механика отклика и чаты.
* **Сквозные процессы (End-to-End):** Проверка почтовых и push-уведомлений, выгрузки файлов (резюме в PDF/Docx).

### День 5: Безопасность и граничные состояния
* **Security Sanity Check:** Поверхностный аудит разграничения прав доступа и фильтрации пользовательского ввода.
* **Network Throttling:** Тестирование поведения интерфейса при нестабильном сетевом соединении и высоких задержках.

---

## 2. Ключевые сценарии для проверки

### Модуль соискателя
1. **Управление резюме:** 
   * Создание, редактирование и экспорт профиля в PDF.
   * Корректность применения настроек приватности (видимость профиля для разных категорий компаний).
2. **Поисковый движок:** 
   * Корректность работы фильтров, сортировок и полнотекстового поиска при сложных комбинированных запросах.
3. **Механика отклика:** 
   * Подача заявки на вакансию (с сопроводительным письмом и без).
   * Синхронизация статусов в личном кабинете и работа чата соискатель-HR.

### Модуль работодателя
1. **Публикация вакансий:** Заполнение форм, прохождение модерации, управление статусами (активна/архив).
2. **Управление откликами:** Перевод кандидатов по этапам воронки найма.
3. **Монетизация:** Списание лимитов и баланса при открытии контактных данных соискателей.

## 3. Наборы тестовых данных (Test Data)

| Категория | Тестовые данные / Входные значения | Что проверяем |
| :--- | :--- | :--- |
| **Текстовые поля** | Спецсимволы, Unicode, HTML/JS-инъекции (`<script>`, `alert`), строки > 10 000 символов | Устойчивость к экранированию (XSS), корректность обрезки и валидации строк |
| **Числовые и финансовые поля** | `0`, отрицательные значения, значения с плавающей точкой, экстремально большие числа | Граничные значения зарплатных вилок и бюджета вакансий |
| **Файловый ввод** | Файлы с подмененным MIME-типом (`.exe` с расширением `.pdf`), поврежденные файлы, объем > 50 МБ | Валидация типов файлов, ограничение размера, безопасный парсинг |
| **Даты и время** | Даты из будущего в опыте работы, пересекающиеся периоды, смена часовых поясов | Валидация хронологии в резюме и времени записи на собеседование |

## 4. Критические риски и уязвимые места

1. **Разграничение прав доступа:**
   * Risk: Доступ к чужим резюме, откликам или чатам путем прямой подмены идентификаторов (`id`) в API-запросах.
2. **Компрометирование персональных данных:**
   * Risk: Отображение скрытых контактов соискателя в коде ответа API (Response Payload), даже если на UI они замаскированы.

1. **Спецификации:** Есть ли актуальная документация по API (Swagger/OpenAPI)?
